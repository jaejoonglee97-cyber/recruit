# 그리팅 없이 자체 채용 페이지로 운영하기 — 비교 메모

현재 재단은 재단 홈페이지에 공지(예: `asan-nanum.org/notice/...`)를 올리고, 지원은 그리팅 채용 홈(`asannanum.career.greetinghr.com`)에서 받습니다.
이 저장소의 시제품은 그 두 곳의 역할을 **한 사이트**로 합친 모습을 보여 줍니다.

## 1. 그리팅 채용 홈의 기능별로 시제품에 넣은 내용

| 그리팅 채용 홈 | 자체 페이지 (이 시제품) | 위치 |
| --- | --- | --- |
| 비전 문구 · 재단 소개 | 같은 구성, 4개 사업 영역 카드 추가 | 홈 상단, `#about` |
| 채용 중인 공고 + 직군·경력·고용형태·근무지 필터 | 같은 4개 필터 + 진행 상태 필터, 조건별 공고 수 표시, 주소(URL)에 필터가 남아 공유 가능 | 홈 `#jobs` |
| 채용 알림 서비스 (외부 설문 폼으로 연결) | **사이트 안에서 바로 신청**, 관심 직군 선택, 수신 동의, 수신 거부. 담당자 화면에서 구독자 확인·공고별 발송(중복 발송 방지) | 홈 공고 아래, 관리자 `알림` 화면 하단 |

| 푸터 SNS (페이스북·블로그·유튜브) | 같은 3개 채널, 모든 공개 화면 하단 | 푸터 |

## 2. 자체 구축으로 얻는 것

- **한 주소에서 끝남**: 공지 → 지원 → 결과 확인 → 증빙 제출 → 면접 안내 → 최종 발표가 재단 도메인 안에서 이어짐 (예: `recruit.asan-nanum.org`)
- **재단 업무에 맞춘 흐름**: 증빙서류 항목별 대조·보완 요청, 4대보험 대체 서류, 마감 판정 기준처럼 재단 기획서(5~10장)에 적힌 규칙을 그대로 구현
- **데이터 소유**: 지원자 정보·평가 기록이 재단 명의 DB에 남음. 서비스 해지 시 데이터 이전 문제가 없음
- **디자인 일관성**: 재단 홈페이지와 같은 색·서체·톤
- **알림 구독자 직접 관리**: 외부 설문 폼에 흩어진 명단 대신 사이트 안에서 동의·해지 이력까지 관리

## 3. 대신 재단이 직접 책임지게 되는 것

그리팅이 대신 해 주던 일을 재단(또는 위탁 개발사)이 맡아야 합니다. 운영 전 필수 항목은 README의 ‘운영 버전으로 가려면’과 같습니다.

| 항목 | 내용 |
| --- | --- |
| 서버·DB·파일 저장소 | 지원서·증빙 원본 보관 (서울 리전, 비공개 저장소, 짧은 만료 링크) |
| 보안 | 서버 측 권한 검사, 관리자 2단계 인증, 정기 점검, 취약점 대응 |
| 개인정보 | 수집·이용 동의서, 처리방침, 보유기간·파기, 위탁 계약(DPA), 유출 시 신고 체계 |
| 메일 발송 | 인증번호·결과 안내·채용 알림 메일, 반송 처리, 수신 거부 링크 |
| 운영·유지보수 | 장애 대응, 공고 시즌 트래픽, 브라우저 호환, 담당자 교육 |
| 콘텐츠 편집 | 지금은 `seed.js` 수정 → 운영 버전은 관리자 화면에서 공고·FAQ·제도 문구 편집 |

## 4. 권장 순서

1. **이 시제품으로 내부 합의**: 화면·흐름·문구를 실무자와 확인 (지금 단계)
2. **병행 운영 1회**: 한 공고(예: 수시채용 1건)만 자체 사이트로 받고, 나머지는 그리팅 유지
3. **운영 버전 구축**: 서버·DB·인증·메일·개인정보 문서 갖춘 뒤 더미 데이터로 보안 점검
4. **전환**: 재단 홈페이지 공지의 ‘지원하기’ 링크를 자체 사이트 공고 주소로 교체, 그리팅 구독자에게 재동의 안내

> 그리팅 이용료와 자체 구축·유지 비용의 비교는 견적이 필요해 이 메모에 넣지 않았습니다. 자체 구축은 초기 개발비보다 **매년 드는 보안·유지보수 인력**이 더 큰 비용이 되는 경우가 많으니, 연간 채용 건수와 함께 비교해 주세요.
