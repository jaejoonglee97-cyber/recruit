# 통합 채용시스템 시제품 (데모)

지원서 작성부터 서류 결과 확인, 증빙서류 제출·보완, 면접 안내, 최종 발표까지 한곳에서 이어지는 채용 웹사이트의 **클릭형 시제품**입니다.
「통합 채용시스템 분석 및 구축 기획서 v0.1」의 13.1 ‘1차 구축’ 범위를 화면과 데이터 흐름으로 옮겼습니다.

> ⚠ **데모 전용**: 공고·지원자·담당자·연락처는 모두 가상입니다. 서버·DB 없이 동작하며, 입력값은 방문자 브라우저(localStorage)에만 저장됩니다. 실제 지원서·증빙을 받는 용도로 쓰면 안 됩니다.

## 바로 보기

| 화면 | 주소 | 비고 |
| --- | --- | --- |
| 채용 홈 | `#/` | 재단 소개·공고(직군·경력·고용형태·근무지 필터)·채용 알림 신청·일하는 방식·근무 환경·FAQ·SNS — 그리팅 채용 홈을 대체하는 구성 ([비교 메모](docs/greeting-vs-self.md)) |

상단 띠의 **데모 설정**에서 데모 기준 시각(마감 직전·직후, 면접일 등)을 바꾸고, 자동저장 실패를 재현하고, 면접 평가 샘플을 채우고, 데이터를 초기화할 수 있습니다.

## 추천 시연 순서 (약 10분)

1. **공고 → 지원**: 로그인에서 새 이메일로 인증 → ‘2026 MARU 커뮤니티 매니저’ 지원서 작성(한 페이지·오른쪽 목차, 자동저장·글자 수·제출 전 검증) → 최종 제출 → 접수번호 확인
2. **서류 합격자의 할 일**: 가상 지원자 `최유나`(일부 제출·암호 PDF 오류)로 로그인 → 지금 할 일 → 증빙 제출. 파일명에 ‘암호’를 넣으면 검사 실패가 재현됨
3. **증빙 대조**: 담당자 로그인 → `윤가람(증빙 확인 담당자)` → 지원서 기재 내용과 파일을 나란히 보고 확인 완료·보완 요청
4. **보완 요청 → 재제출**: 보완 요청한 지원자로 로그인해 재제출 → 이전 확인 결과가 승계되지 않는지 확인
5. **면접**: `방서진`(일정 문의)으로 응답 확인 → `한지수(채용 담당자)`가 일정 변경 → 지원자 화면에 v2 일정과 변경 이력 표시
6. **최종 발표**: 데모 설정 → ‘면접 평가 샘플 채우기’ → 한지수가 결과안 작성 → `오민석(채용 책임자)`이 확정 → 발표 미리보기 → 실행. 반송 메일이 있어도 지원자 화면에서 결과 확인 가능
7. **마감 판정**: 데모 설정에서 ‘증빙 마감 직후’로 바꾼 뒤 제출 → 지연 제출로 기록

## 로컬에서 실행

빌드 도구가 필요 없습니다. 아무 정적 서버로 열면 됩니다. (ES 모듈을 쓰므로 `index.html`을 파일로 직접 열면 동작하지 않습니다.)

```powershell
powershell -ExecutionPolicy Bypass -File scripts/serve.ps1 -Port 5173
```

브라우저에서 `http://localhost:5173` 접속.

## 배포 (GitHub → Vercel)

1. GitHub에서 새 저장소를 만들고(비공개 권장) 이 폴더를 올립니다.
2. Vercel → **Add New → Project** → 저장소 선택
3. Framework Preset: **Other**, Build Command: 비움, Output Directory: 비움(루트) → Deploy

`vercel.json`이 검색 노출 차단(`X-Robots-Tag: noindex`), 보안 헤더(CSP, 프레임 차단 등)를 적용합니다. `scripts/`, `docs/`, `.claude/`는 `.vercelignore`로 배포에서 제외됩니다.

## 운영 버전으로 가려면 (시제품에 없는 것)

이 시제품은 **화면과 흐름을 합의하기 위한 것**입니다. 실제 지원자 정보를 받기 전에 아래가 필요합니다.

- **서버와 DB**: 지원서·평가·증빙 연결 정보를 기관 명의 DB에 저장 (예: Next.js + Supabase/PostgreSQL). 리전은 서울로 지정하고, 위탁 계약(DPA)을 체결
- **서버 측 권한 검사**: 지금은 화면에서만 역할을 나눕니다. 운영에서는 모든 요청을 서버에서 검사하고 행 수준 보안(RLS)을 적용
- **비공개 파일 저장소**: 증빙 원본은 비공개 버킷, 짧은 만료의 다운로드 링크, 업로드 후 악성·손상 검사
- **실제 인증·메일**: 이메일 인증번호 발송, 결과 안내 메일, 반송 처리
- **개인정보 문서**: 수집·이용 동의서, 처리방침, 보유기간·파기 정책 (기획서 11장, 17장)
- **보안 점검**: 키를 `.env`·환경변수로만 관리, 더미 데이터로 보안 검증을 끝낸 뒤 실데이터 투입
- **브랜드 사용**: 재단 로고(`assets/brand/`)는 재단 공식 웹사이트에서 받은 파일입니다. 외부에 공개하기 전에 재단의 사용 승인을 확인해 주세요.
